# Execution notes

- Initial pilot attempt stopped before loading any maps: the preflight check counted all 57 entries in `sources.json` (54 maps plus three metadata files) as maps. The check was corrected to count only `.nii.gz` entries; no result artifacts were produced by the failed attempt.
- First full run passed input validation but was rejected after inspection because the maximum-statistic accumulator had not been initialized, contaminating permutation p-values. The accumulator now starts at negative infinity and the full inference was rerun; outputs from the rejected run were overwritten by the corrected run.
- Second full run was rejected after inspection of very large permutation maxima. The initial explanation that a one-sample t statistic is bounded by sqrt(n-1) was incorrect. A recomputed permutation variance can approach zero; the final method instead uses the observed voxelwise standard error as a fixed scale for all sign flips, avoiding that degenerate denominator and retaining the observed one-sample t statistic under the observed signs. This method change is specified in `analysis/protocol.md`.
- During final review, the BH sensitivity map was found to have been ranked by max-T p rather than uncorrected p; its ordering was fixed and all outputs regenerated. An initial strict validator tolerance also rejected the saved maps because NIfTI outputs are float32; independent comparisons now use a prespecified 1e-6 storage tolerance.
- Accepted analysis uses the fixed input maps after manifest verification. See `summary.json` and `input_qc.tsv` for the run-specific checks.
- Final validation matches SciPy's observed t/p maps within float32 tolerance and reconstructs the saved max-T p map within 3.0e-8. It reproduces the corrected voxel count and confirms no corrected vmPFC voxels.
